# gp-009 — Light execution profile for both tools

STATUS: DONE
OWNER: Claude Code

Promote the user's project-local Codex prototype (`--feature --light` in
D:/Pet/Ground_Truth, Codex-only) into the canonical generator, generalized so
Claude Code supports it too. `claim --profile light` dispatches one expert-tier
developer that owns implementation, tests and one repair pass, then one
simple-tier closer completes reviewer and verifier sequentially. The recorded
profile is immutable across resume/recovery; Blender/critical-lifecycle/
concurrency/replay-codec/data-loss risk and any role outside developer/
reviewer/verifier require the standard profile; incompatible with `--batch`.

`profiles.light`/`claude.profiles.light` in model-policy.json optionally pin an
explicit implementer/closer model; otherwise the expert/simple tier is derived
per tool. In Claude Code the closer's pinned frontmatter effort can exceed the
simple tier's target — reported honestly via `tier_reasoning_effort`/
`effort_source`, the same mechanism gp-008 built for tiers.

Scope: model-policy schema/template, gp_work.py (route/claim/assign/
context_packet/resume/metrics/CLI), runbooks (feature.md x2, contract-work.md,
{{PREFIX}}.md), marketplace texts, docs/WORKFLOW.md and USAGE.md. Released as
1.3.0. Re-adopted D:/Pet/Ground_Truth for both tools (--force); its hand-edited
Codex prototype text was replaced by the canonical rendering (archived under
its own archive/gp-bootstrap/), Ground_Truth's local
pipeline/tests/test_light_profile.py still passes against the regenerated
.codex/scripts/gp_work.py. Live dispatch of a light-profile assignment through
either tool is not verified here.
