# Pipeline review and Codex deployment

Reviewed baseline: `53af335` (v0.1.0). Result: v0.2.0 working tree, 2026-09-04.

The architecture is useful: one template source, lazy mode runbooks, independent
review roles, deterministic gates, frozen art profiles, and a separate provider
adapter. The baseline was an early skeleton rather than an operational Codex
pipeline. Its largest risks were undiscoverable entry points and false-positive
gates, not a shortage of specialist agents.

## Findings addressed

| Priority | Baseline failure and consequence | Resolution |
|---|---|---|
| P1 | `--tool=codex` only changed a directory name. No discoverable skill or Codex root instructions; Claude model/tool frontmatter remained. | Personal `gp-dev`, project `SKILL.md`, `AGENTS.md`, and 14 native TOML adapters derived from canonical role Markdown. Models are inherited. |
| P1 | `--force` copied over state and rendered broad globs of existing files; the memory index was rewritten every time. | Stage before deployment, archive replaced runtime files, preserve custom instructions/state/boards/art and append index entries. |
| P1 | Runner returned `pass:true` when gdUnit4 was absent. | Report `test_harness_missing`; no test execution means no green build/test gate. |
| P1 | Replay accepted zero or one run; a process could fail after printing a hash. Balance ignored silent runs. | Validate counters and harness JSON/seed, require at least two replays, and reject process failures or incomplete seed batches. |
| P1 | Visual gate accepted old output files and an empty shot list. `--headless` also disabled the rendering needed for actual screenshots. | Archive previous outputs, require successful process plus fresh output, reject an empty list and use a rendering-capable display. Export also archives stale APKs. |
| P1 | Asset validation treated a missing locked palette as a warning. Provenance checked field presence, not referenced hashes. Generation trusted an old manifest without verifying current files. | Missing palette and empty image fail; validate the shipped spec/provenance schema vocabulary, prompt hash, current reference file set/hashes, and reference membership. |
| P2 | Error messages embedded arbitrary paths directly in JSON; quoted paths/control characters broke the one-line contract. Native Python calls could fail when MSYS argument conversion was disabled. | Shared JSON escaping and native-path conversion, tested with quotes, tabs, newlines and Windows paths. |
| P2 | Codex art runbooks always waited for a human despite an available native image tool. Edit generation omitted its source and edit goal. | Capability-aware host invocation, external-file fallback, edit conditioning, correct operator metadata and archived prior outputs. Unsent Gemini seeds are no longer recorded as accepted parameters. |

Codex adapters use the documented [skill discovery locations](https://learn.chatgpt.com/docs/build-skills)
and [native agent configuration](https://learn.chatgpt.com/docs/agent-configuration/subagents).
Godot documents that [headless mode disables rendering](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html).

## Improvements to prioritize next

1. **P1: finish one real playable vertical slice.** Create a minimal actual Godot
   game with pinned engine and gdUnit4 versions, `sim_harness.tscn`, and a
   rendering-capable `shot.tscn`. Pass replay, unit tests, a real screenshot,
   Android export, and one device launch. Deterministic script tests cannot prove
   those integrations. Keep this work in a game repo; promote reusable harness
   templates only after their contract works against the engine.
2. **P2: make profile coverage explicit.** Profiles declare `max_tones_per_object`
   but the validator does not implement it. Light direction, part alignment and
   visual taste also remain director checks. Add a rule-to-check coverage table
   and report unimplemented machine rules; add fixture corpora for each style
   before presenting a profile as fully enforced. Decide alpha rules by asset
   purpose/tier so opaque promotional art has an explicit contract.
3. **P2: bind provenance to exact image bytes.** v1 binds the prompt and reference
   sheet but has no image digest field. Replacing an image while keeping its
   otherwise valid provenance can still pass. Introduce image SHA-256 and frozen
   per-attempt prompt snapshots through a versioned schema migration; per this
   repo's SemVer rule, changing the JSON shape requires a major release.
4. **P2: add CI against real environments.** Run the regression suite on Linux,
   macOS and Git Bash, then a pinned Godot job and a rendering-capable visual job.
   Add execution deadlines so a hung engine/harness cannot hold an invocation
   forever. Retain logs and screenshots as run artifacts.
5. **P3: measure the pipeline before adding more agents.** Track retries per
   asset, gate false positives, review reversals and time per completed SPEC.
   Use these observations to decide whether audio/VFX/device-performance
   specialists are worth their context and maintenance cost.

## Validation and its limits

- `bash tests/smoke.sh`: nine regression groups passed. Both tools render in
  paths containing spaces; tests cover native adapter parsing, marker removal,
  non-interactive validation, update preservation, JSON escaping, fake-engine
  failure modes, successful replay/balance, stale screenshots, and the offline
  art prompt/register/validate/drift flow.
- All shipped style/projection/schema JSON parses, Python files compile, and
  touched Bash scripts pass `bash -n`. `git diff --check` is clean.
- Codex CLI 0.153.1 `app-server` returned `gp-dev` (user scope) and `gp` (repo
  scope), both enabled, from `skills/list`. No discovery error for either skill.
- An independent skill forward-test ran `$gp --gates` in the sandbox and
  correctly reported `project_missing` rather than treating exit code 0 as pass.
- No real Godot build/export, named-agent implementation workflow, Android device
  run or live image generation was performed. The tests use an explicit fake
  engine and deterministic pixel fixtures; they do not establish art quality.

Local evidence is retained under `out/regression-final.log`,
`out/codex-discovery.json`, and `out/codex-gates-forward-test.md`.
The supplemental graph is in `graphify-out/`; it has partial semantic coverage
and unresolved links, and predates the new adapter files. It is navigation help,
not authoritative validation evidence.

## Local deployment

- Personal entry point: `C:/Users/Admin/.codex/skills/gp-dev/SKILL.md`.
- Repeatable installer: `bash install-codex.sh`.
- Generated sandbox: `D:/Pet/game-pipeline/out/codex-demo`.
- Invoke `$gp --gates` after opening that sandbox in Codex, or `$gp-dev` from a
  chosen game repo to install/run the reusable pipeline.
- The sandbox contains the pipeline, not a game. `game/project.godot` and STYLE
  LOCK do not exist there. A successful bootstrap is not a game-readiness pass.

Existing root instructions, state, boards, profiles and memory are preserved on
upgrade. Replaced runtime files remain under `archive/gp-bootstrap/`. The personal
installer retains prior adapters in its sibling `archive/` directory. No global
model, permission or trust setting is changed.
